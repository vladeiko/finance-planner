# Git: коммиты и ветки

## Коммиты — Conventional Commits

```
<тип>(<область>): <что сделано, по-русски, с маленькой буквы, без точки>

<необязательное тело: зачем и что важно знать>
```

Примеры:
```
feat(paycheck): раскидка свободных денег по счетам
fix(domain): лишняя копейка уходила в аванс вместо зарплаты
test(domain): примеры остатка из спецификации
docs(spec): ипотека как калькулятор без хранения
chore: каркас проекта на Vite
```

**Типы:** `feat` — новая возможность · `fix` — исправление · `refactor` — без изменения поведения · `test` — только тесты · `docs` — `spec/`, README, комментарии · `style` — только CSS/вёрстка без изменения поведения · `build` — сборка, PWA, зависимости · `chore` — прочее (конфиги, `.claude/`).

**Области:** слои `domain`, `storage`, `app`, `ui`; экраны `paycheck`, `history`, `plan`, `mortgage`, `settings`; а также `spec`, `pwa`. Область можно опустить, если изменение сквозное.

- Заголовок — до ~72 символов, отвечает на «что сделано».
- Один коммит — одно логическое изменение. Правка спецификации, за которой следует код, — допустимо одним коммитом, если это одна задача.
- Ломающее изменение формата данных: `!` после области (`feat(storage)!: …`) и в теле — какая миграция.
- Коммит создаётся **только после подтверждения пользователя**.

## Ветки

- Основная — `master`. Мелкие изменения можно коммитить прямо в неё.
- Для крупной или экспериментальной работы — ветка `<тип>/<кратко-латиницей-через-дефис>`:
  `feat/free-money-distribution`, `fix/kopeck-rounding`, `chore/pwa-setup`.
- Вливание в `master` — squash или fast-forward, чтобы история `master` состояла из коммитов по правилам выше.
