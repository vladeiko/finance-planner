# Порядок работы

- Общение, документация, комментарии в коде и описания коммитов — на русском. Идентификаторы в коде — на английском.
- `spec/` — источник истины. Перед работой читай `spec/progress.md`, по необходимости — нужный раздел `product.md` / `data-model.md` / `architecture.md`.
- **Сначала спецификация, потом код.** Если задача меняет правила расчёта, модель данных или архитектуру — сначала правим `spec/` (скилл `spec-change`), потом код и тесты.
- Если код и спецификация расходятся — не «чини» молча ни то, ни другое: спроси пользователя, что верно.
- Работаем по этапам из `progress.md`. Не делай работу следующих этапов «заодно».
- После завершённого куска работы — скилл `finish-step`: проверки, обновление `progress.md`, предложение коммита.
- Новые зависимости — только с обоснованием и согласием пользователя. Принцип проекта: без библиотек там, где хватает 30 строк своего кода.
- Пакетный менеджер — pnpm. Проверки: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm e2e` (если затронут UI).
- UI проверяется через Playwright (headless Chromium): e2e-тесты в `e2e/`, для визуальной проверки — скриншоты в мобильном (375px) и десктопном размере, светлая и тёмная тема.
