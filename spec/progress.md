## Не забыть

- **Защита цепочки поставок** (отложено 2026-10-04, вернуться ~2026-10-12…18). Добавить `pnpm-workspace.yaml` с `minimumReleaseAge: 10080` (7 дней; в pnpm 11 по умолчанию только 1 день) и `trustPolicy: no-downgrade`. Отдельным коммитом `build: ...`. Что выяснили при первой попытке:
  - на 2026-10-04 в лок-файле 83 версии моложе 7 дней (прямые: `oxlint 1.86.0`, `vite 8.3.2`, `vitest 5.0.3`, `@types/node 26.6.4`, остальное — их транзитивные). Через неделю-другую проблема уйдёт сама, откатывать версии не придётся;
  - проверка идёт по существующему лок-файлу ещё до разрешения версий: если что-то не проходит, лок-файл надо пересобрать (`pnpm clean --lockfile` / удалить `pnpm-lock.yaml`) и сверить diff;
  - `trustPolicy: no-downgrade` даёт ложные срабатывания на старых версиях без provenance: `why-is-node-running@3.2.2` (от vitest), `@trickfilm400/rollup-plugin-off-main-thread@3.0.0-pre1` (от workbox-build, требуется ровно она), `semver@6.3.1` (бэкпорт после 7.x). Точечные исключения не сходятся — помогает `trustPolicyIgnoreAfter: 43200` (не проверять версии старше 30 дней), с ним установка прошла;
  - pnpm печатает только первые 20 нарушений — полный список удобнее собрать скриптом по датам из реестра npm.
- Когда oxfmt выйдет в GA — рассмотреть переход с Prettier.

| 2026-10-04 | Ипотека — отдельный калькулятор без хранения: баланс, платёж, вношу в месяц → досрочка (резерв только если взнос < платежа).
