# Документация проекта Finance Planner

Здесь живёт описание приложения: что оно делает, по каким правилам считает, как устроено и что уже сделано.
Документы — источник истины: если код и спецификация расходятся, сначала разбираемся, что верно, и обновляем одно из двух.

## Файлы

| Файл | Что внутри |
|---|---|
| [product.md](./product.md) | Зачем приложение, термины, функции и **правила расчётов** (распределение, разовые траты, ипотека) |
| [data-model.md](./data-model.md) | Сущности, поля, инварианты хранения |
| [architecture.md](./architecture.md) | Стек, структура проекта, слой хранения, будущая синхронизация |
| [sync-research.md](./sync-research.md) | Исследование облачных хранилищ для синхронизации: что проверено, что подходит, правовой аспект |
| [progress.md](./progress.md) | Что сделано, что дальше, журнал решений, открытые вопросы |

## Как продолжать работу (в т.ч. в новой сессии / на другом устройстве)

1. Прочитать `progress.md` — там текущий этап и следующий шаг.
2. По необходимости — нужный раздел `product.md` / `data-model.md` / `architecture.md`.
3. После завершения куска работы обновить `progress.md`: отметить сделанное, записать принятые решения и новые вопросы.
4. Если поменялись правила или модель — сначала правим спецификацию, потом код.

## Соглашения

Правила работы, git и слоёв — в [`.claude/rules/`](../.claude/rules/); типовые процедуры (завершение шага, изменение спеки, новый экран, миграция схемы) — в [`.claude/skills/`](../.claude/skills/).
