# Синхронизация: исследование хранилищ

Проверено 2026-10-07. Итог для архитектуры — в [architecture.md](./architecture.md#будущая-синхронизация-не-mvp).

## Требования

- Без своего бэкенда: приложение статическое, лежит на GitHub Pages.
- Работает при белых списках (доступны только российские сервисы).
- Без входа через иностранные аккаунты.
- Запись и чтение прямо из браузера. Упирается в CORS: запрос с `Authorization` и `Content-Type: application/json` требует preflight, сервер должен явно разрешить эти заголовки; прочитать ответ можно, только если есть `Access-Control-Allow-Origin`.

## Итоги

| Хранилище | Запись из браузера | Чтение из браузера | Вывод |
|---|---|---|---|
| Яндекс.Диск | да | **нет** | не подходит |
| GitVerse | **нет** | да | не подходит |
| GitFlic | preflight пропускает `authorization, content-type` | не проверено | **кандидат**, нужна проверка по документации API |
| Google Drive | не проверялось | не проверялось | не берём: вход через Google, нет в белых списках |
| Свой прокси (Cloudflare Worker) | да | да | не берём: это бэкенд, и домен не в белых списках |

- **Яндекс.Диск.** Загрузка работает: `cloud-api.yandex.net` и `uploader*.disk.yandex.net` отдают CORS. Скачивание — нет: `downloader.disk.yandex.ru` без `Access-Control-Allow-Origin` и с 403, и для приватных, и для публичных файлов. Обходы не работают: WebDAV без CORS, `<script src>` блокируется (файл отдаётся как `text/plain`).
- **GitVerse.** Файлы пишутся через `PUT /repos/{owner}/{repo}/contents/{path}` с JSON-телом, сервер принимает только `application/json`. Preflight разрешает один заголовок — `Authorization`, поэтому браузер JSON не отправит (с curl запись работает). Чтение работает. Если GitVerse разрешит `Content-Type`, вариант вернётся в игру.
- **GitFlic.** Preflight на `api.gitflic.ru` с нашим origin пропускает `authorization, content-type`. Формат API, токены и доступность при белых списках не проверены, документацию найти не удалось.

## Правовой аспект

Закон о штрафах (199-ФЗ, ст. 13.55 КоАП, с 7.07.2026) запрещает российским владельцам сайтов и приложений авторизовать пользователей через иностранные сервисы (ст. 8 ч. 10 149-ФЗ). В приложении авторизации нет: ни аккаунтов, ни сервера, облако — личное хранилище пользователя. Поэтому закон к синхронизации не относится. Чтобы так и оставалось: токен вводится вручную, без OAuth и кнопки «Войти через …», синхронизация необязательна.
